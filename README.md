# dotfiles

Исходные конфиги лежат в `configs/` и повторяют структуру HOME:
`configs/.zshrc`, `configs/.p10k.zsh`, `configs/.config/nvim/` и т. д.
Пакеты macOS/Arch, Git-плагины, сборки и транзакции описаны в одном
`dependencies.yaml`. Make запускает Ansible; ссылки создаёт GNU Stow.

## Установка одной командой

После клонирования репозитория:

```sh
make install
```

На macOS нужны Git, Make и Homebrew с Command Line Tools; на Arch — Git,
Make и sudo/pacman. Ansible, его коллекция `community.general` и Stow
устанавливаются автоматически. Arch может запросить пароль sudo; недостающие
пакеты устанавливаются вместе с полным обновлением системы.

Перед установкой зависимостей macOS проверяется линковка компилятором Apple
с доступными SDK: сначала с текущим, затем с остальными, начиная с новых.
Если SDK 27 не поддерживается установленным линковщиком, установщик автоматически
выберет совместимый SDK, например 26.5. Проверенный выбор сохраняется локально
в `$XDG_DATA_HOME/dotfiles/native-toolchain.json` (по умолчанию
`~/.local/share/dotfiles/native-toolchain.json`) и используется для SketchyBar,
AeroSpace Swipe и парсеров Neovim. Системные SDK и настройка `xcode-select`
не изменяются. Обновление Xcode/Command Line Tools потребуется только если
ни один из установленных SDK не проходит проверку.

Приложения macOS, уже установленные вручную, повторно не скачиваются и не
передаются под управление Homebrew. Установщик получает пути `.app` из
метаданных cask и проверяет наличие `Contents/Info.plist` по пути установки
и в `~/Applications`. Недостающие приложения и шрифты устанавливаются как
обычно. Это позволяет, например, заранее установить iTerm с сайта и затем
запустить `make install`.

Порядок установки:

1. Подготовить Ansible/Stow, проверить TARGET, родительские каталоги и конфликты.
2. Установить недостающие зависимости, скачать плагины и собрать нативные программы.
3. Сформировать отдельный снимок выбранных конфигов, исключая секреты через Stow.
4. Сохранить прежние файлы, каталоги и симлинки; подключить снимок через Stow.
5. Инициализировать Neovim и настройки приложений; проверить загрузку плагинов,
   версии по lockfile, Mason-инструменты и парсеры. Только после успеха сохранить чекпойнт.
6. Запустить выбранные desktop-приложения и сервисы macOS.

Если шаг 2 не удался, активация конфигов не начинается. При обычной ошибке
шагов 4–5 Ansible восстанавливает прежние конфиги и завершает установку с ошибкой.
Программы, плагины и кэши, скачанные во время подготовки, остаются.

macOS получает все конфиги, Arch — общие. Повторный запуск приложений доступен
через `make start`; `make install START=0` пропускает запуск. `make sync` по умолчанию
не запускает приложения; `make sync START=1` включает запуск. Разрешения Accessibility и авторизация сервисов требуют
действий пользователя. Docker/Kubernetes требуют настроенного daemon/контекста.

## Снимки, повторный запуск и откат

Активные симлинки ведут в снимок внутри `~/.local/state/dotfiles/`, а не
непосредственно в рабочую копию Git. Поэтому `git pull` и редактирование
`configs/` не меняют активную конфигурацию до следующего `make install`.
Старые снимки сохраняются, чтобы откат возвращал и прежнее содержимое конфигов.

Если выбранные файлы совпадают с последним снимком и его ссылки на месте,
повторная установка сохраняет ссылки и последний чекпойнт. Готовность плагинов
проверяется повторно; временные операции Ansible и нативные сборки могут
отмечаться как `changed`.

Neovim загружает плагины с ограниченной параллельностью и повторяет неудачную
установку до трёх раз. Уже установленные версии, совпадающие с lockfile,
не требуют повторного Git fetch. Mason повторяет неудачные установки и снимает
оставшуюся после сбоя блокировку только если её процесс завершился.
Повторная проверка Neovim отдельно: `make test-nvim`.

```sh
make rollback           # вернуть состояние до последней успешной активации
make recover            # восстановиться после прерванной установки
```

Повторный `rollback` идёт дальше по истории. Он восстанавливает и существовавшие
раньше обычные файлы, и каталоги, и чужие/битые симлинки. Текущее состояние
перед откатом перемещается в `displaced/` соответствующего чекпойнта: поздние
локальные файлы не удаляются. Пустые родительские каталоги, созданные установкой,
удаляются только если они действительно пусты.

`recover` читает маркер незавершённой транзакции. Он восстанавливает только те
оригиналы, которые успели попасть в backup, и умеет завершать прерванный откат.
Если прерывание произошло после фиксации успешной установки, он завершает
служебную запись без отката конфигов. Повторный `recover` без незавершённой
транзакции ничего не меняет в конфигах.

История хранится в `${XDG_STATE_HOME:-~/.local/state}/dotfiles` с режимом 700;
внутри могут быть приватные пользовательские конфиги. История автоматически
не очищается. Для каждого другого `TARGET` нужен отдельный `STATE_DIR`:

```sh
make install-btop TARGET=/tmp/test-home STATE_DIR=/tmp/test-dotfiles-state
make rollback TARGET=/tmp/test-home STATE_DIR=/tmp/test-dotfiles-state
```

TARGET должен существовать. Для Neovim, Hammerspoon, iTerm2 и Swipe допускается только
настоящий HOME: их инициализация затрагивает данные текущего пользователя.

## Конфликты и границы транзакции

По умолчанию заменяется **выбранный конфиг целиком**: например, существующая
`~/.config/nvim` перемещается в backup вместе с дополнительными локальными файлами.
Автоматического слияния файлов нет. Другие конфиги внутри `~/.config` не затрагиваются.
Чтобы отказаться от замены при конфликте, используйте `make install CONFLICTS=abort`.
Bootstrap Ansible/Stow может произойти до такой проверки.

| Ситуация | Поведение |
| --- | --- |
| Обычный файл или каталог на месте конфига | Сохраняется целиком; затем подключается новый снимок |
| Чужой или битый симлинк на месте конфига | Сохраняется сам симлинк; его внешний адресат не изменяется |
| Файл или битый симлинк вместо родительской `.config` | Установка останавливается до установки основных зависимостей |
| Ошибка скачивания или сборки зависимости | Старые конфиги остаются активными; повторите `make install` |
| Ошибка Stow или инициализации | Ansible восстанавливает оригиналы; установка возвращает ошибку |
| Второй установщик одновременно | Блокировка не позволяет одновременно менять конфиги |
| Принудительное завершение процесса | Маркер и backup остаются; после остановки процесса выполните `make recover` |
| Конфликт при повторном восстановлении | Обе копии сохраняются; восстановление останавливается для ручного сравнения |

Это восстановимая транзакция конфигов, **не общая ACID-транзакция всей системы**.
Homebrew/pacman и обновление Arch не откатываются; автоматического удаления
установленных пакетов нет. Кэши/бинарники плагинов Neovim, nvm и других менеджеров
также находятся вне транзакции. Настройка пути Hammerspoon и LaunchAgent Swipe
включены в восстановление; состояние запущенных процессов и разрешения macOS — нет.
Запуск приложений происходит после commit: если он завершился ошибкой, конфиги
остаются установленными. После выдачи разрешений можно повторить `make start`
или вернуть конфиги через `make rollback`.

Stow меняет ссылки последовательно: работающие приложения могут кратковременно
видеть промежуточное состояние. Его [проверка конфликтов](https://www.gnu.org/software/stow/manual/html_node/Conflicts.html)
предшествует применению операций, но сама по себе не даёт отката после сбоя ввода-вывода.
Ansible [`rescue`](https://docs.ansible.com/projects/ansible/latest/playbook_guide/playbooks_blocks.html)
не исполняется при `kill -9`,
падении машины или потере соединения; для этого оставлены журнал и `recover`.
Отказ диска, потеря самого backup или параллельные изменения файлов другим
приложением не дают гарантии автоматического восстановления. Для отката всей
ОС необходим отдельный системный backup/snapshot.

## Отдельные конфиги и просмотр

```sh
make install-nvim       # тот же цикл установки и транзакция только для Neovim
make install-zsh        # .zshrc и .p10k.zsh
make deps-nvim          # только зависимости, без активации конфигов
make list               # доступные на этой ОС конфиги
make plan               # списки зависимостей, задачи Ansible и симуляция Stow
DOTFILES_PLATFORM=arch make plan
make start              # запустить desktop-приложения на macOS
make check              # синтаксис YAML
make test               # реальные Stow/Ansible в изолированных временных каталогах
```

Имена конфигов определяются автоматически по `configs/`. После добавления
`configs/.config/tmux/tmux.conf` появится `make install-tmux`, после добавления
`configs/.gitconfig` — `make install-gitconfig`. Зависимости нового конфига
при необходимости добавляются в `dependency_sets` того же YAML. AeroSpace
автоматически включает SketchyBar; Swipe — AeroSpace и SketchyBar.

`make plan` не устанавливает инструменты: если их ещё нет, сначала выполните
`make ansible stow`. План показывает весь выбранный набор зависимостей, а не
только отсутствующие пакеты. Конфликты при политике `backup` обозначают будущую
замену с сохранением оригиналов. `make install DRY_RUN=1` запускает этот план.
`make deps DRY_RUN=1` использует полный Ansible check mode; для него могут
потребоваться сеть, существующие Homebrew taps и каталоги.

Низкоуровневые `make link[-имя]` / `make unlink[-имя]` вызывают Stow напрямую
для рабочей копии и не ведут историю. Они предназначены для ручной работы;
для штатной установки и восстановления используйте `install` / `rollback`.

[Аудит зависимостей всех конфигов](DEPENDENCIES.md),
[подробности Neovim](configs/.config/nvim/README.md).
Секреты передаются отдельно, предпочтительно через `~/.config/zsh/secrets.zsh`.
Локальный `configs/.zsh.secrets` исключён из Git, Stow и снимков; старые архивы
в игнорируемой `.local/` не участвуют в установке.

## Полный конфиг iTerm2 на другом Mac

`configs/.config/iterm2/com.googlecode.iterm2.plist` — полный экспорт
`defaults export com.googlecode.iterm2 -` с исходного Mac. В нём сохранены
все 118 параметров: исходный профиль по умолчанию, шрифты (Hack Nerd Font 16),
окно без шапки, прозрачность/размытие, обе цветовые палитры, именованный preset
`Gruvbox%20Material%20Dark` в Color Presets, горячие клавиши и глобальные настройки.
Этот экспорт заменяет прежний выборочный Dynamic Profile.

```sh
make sync               # обновить все конфиги, без запуска приложений
# либо только iTerm2:
make install-iterm2 START=0
```

Установка подключает полный plist через Stow в `~/.config/iterm2`,
устанавливает Hack Nerd Font и задаёт в iTerm2 **Load settings from a custom
folder** для этого каталога. После завершения **полностью закрой iTerm2 через
Cmd+Q и открой заново**. Восстановленные старые окна могут сохранять прежние
настройки сессий; новое окно использует профиль по умолчанию из полного экспорта.
Ручной выбор профиля `Dotfiles` больше не нужен.

Исходный plist сохраняется целиком. При очередном переносе всех актуальных
настроек экспортируй его снова:

```sh
defaults export com.googlecode.iterm2 - > configs/.config/iterm2/com.googlecode.iterm2.plist
```

Перед активацией установщик сохраняет полный экспорт прежних локальных настроек
в приватном чекпойнте (режим 600). При ошибке или `make rollback` восстанавливается
весь прежний конфиг, включая настройки загрузки. После отката тоже перезапусти
iTerm2. Обратная запись из iTerm2 в управляемый снимок отключена, чтобы выход
из приложения не затирал установленный экспорт. Старый управляемый
`DynamicProfiles/dotfiles.json` сохраняется в backup и удаляется при миграции;
другие Dynamic Profiles остаются на месте. `make link-iterm2` подключает файл,
а штатную загрузку настраивает только `make install-iterm2` / `make sync`.
На Arch пакет iTerm2 пропускается.
